# Índice — REST y contratos de API

REST como **estilo arquitectónico** derivado de restricciones: su árbol de derivación, componentes y conectores, los nueve principios, las cuatro restricciones de la **interfaz uniforme**, el modelo de madurez de **Richardson** y el contrato **OpenAPI** que reemplazó a la hipermedia en la práctica.

## Contenido

1. [[01 - REST como estilo derivado de restricciones]] — Fielding, el método propiedades-restricciones-costos, el árbol de derivación (CS, CSS, C$SS, LC$SS, COD) y qué restricción compra cada propiedad.
2. [[02 - Componentes conectores y el flujo de una petición web]] — Componentes, conectores y elementos de datos con sus nombres actuales, y el flujo de una petición con DNS, proxy y CDN.
3. [[03 - Principios REST y restricciones de interfaz uniforme]] — Los nueve principios, stateless, recurso y representación, URIs opacas, negociación de formato, métodos safe e idempotentes, HATEOAS y el patrón contenedor-ítem.
4. [[04 - Qué no es REST malas prácticas y madurez de Richardson]] — Qué no es REST, malas prácticas en URIs, niveles 0 a 3 de Richardson con el ejemplo de la clínica y la contradicción de thing/1 resuelta.
5. [[05 - OpenAPI y límites de REST]] — Contract-first con OpenAPI, ventajas y limitaciones de REST y cuándo reemplazarlo por gRPC, MOM o GraphQL.
