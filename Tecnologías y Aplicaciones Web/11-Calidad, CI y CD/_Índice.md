# Calidad, CI y CD — índice

Cómo desarrollar "bien" cuando el proyecto crece: qué es la calidad de software y por qué es una responsabilidad, las técnicas para asegurarla (testing, análisis estático y code review), el flujo de trabajo con ramas, pull requests y buenos commits, y la automatización de todo eso con integración y despliegue continuos.

Volver al [[Tecnologías y Aplicaciones Web/_Índice|mapa del ramo]].

> [!note] Origen
> Construido con las slides de la clase de QA, CI y CD (calidad de software, responsabilidades, impacto, QA, análisis estático, linters y ESLint, code review, GitHub flow, convenciones de commits, GitHub Actions, CD y hosting). El ejemplo de ESLint se ejecutó con ESLint 9 y los workflows se validaron como YAML.
