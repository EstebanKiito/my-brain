# Almacenamiento en el cliente — índice

Dónde guardar datos en una aplicación web: por qué conviene almacenar del lado del cliente y cómo manejar cookies desde JavaScript, `localStorage` y `sessionStorage`, la base de datos del navegador (IndexedDB), las cachés (Cache API y CDN) y, del lado del servidor, las bases SQL y las familias NoSQL.

Volver al [[Tecnologías y Aplicaciones Web/_Índice|mapa del ramo]].

> [!note] Origen
> Construido con las slides de la clase de almacenes de información (almacenamiento client-side, cookies desde JS, Cookie Store API, Web Storage, IndexedDB, tipos de caché, Cache API, CDN, bases de datos SQL y NoSQL). Los ejemplos de cookies, Web Storage e IndexedDB se probaron con jsdom y fake-indexeddb.

## Orden de estudio
1. [[01 - Cookies desde JavaScript y Cookie Store API|Cookies desde JavaScript y Cookie Store API]]: por qué guardar en el cliente, `document.cookie` y `cookieStore`.
2. [[02 - localStorage y sessionStorage|localStorage y sessionStorage]]: persistencia, alcance por pestaña y origen, strings y JSON, y cuándo usar cada uno.
3. [[03 - IndexedDB|IndexedDB]]: object stores, versiones, transacciones y llaves.
4. [[04 - Caché, Cache API y CDN|Caché, Cache API y CDN]]: cachés privadas y compartidas, pares request-respuesta y redes de distribución.
5. [[05 - Almacenamiento en el servidor SQL y NoSQL|Almacenamiento en el servidor: SQL y NoSQL]]: relacional, documentos, key-value, vectoriales y grafos.
