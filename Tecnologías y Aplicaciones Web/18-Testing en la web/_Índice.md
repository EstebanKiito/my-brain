# Testing en la web — índice

Cómo comprobar que una aplicación funciona: qué es un buen test y los niveles de testing, cómo aislar una unidad con stubs, mocks e inyección de dependencias, cómo escribir y automatizar tests con Jest, y qué se prueba en el front-end (regresión visual, performance, accesibilidad, end-to-end y componentes de React).

Volver al [[Tecnologías y Aplicaciones Web/_Índice|mapa del ramo]].

> [!note] Origen
> Construido con las slides de la clase de testing (definición, verificación y validación, niveles, ejemplos de tests unitarios, mocks y stubs, TDD, estructura de un test, Jest, matchers, asincronía, mocks, GitHub Actions y tests de front-end con Selenium y Testing Library). Los ejemplos de back-end se ejecutaron con Jest 30.

## Orden de estudio
1. [[01 - Qué es testing y sus niveles|Qué es testing y sus niveles]]: buen test, verificación frente a validación, unitario, integración, sistema, aceptación y TDD.
2. [[02 - Tests unitarios, mocks y stubs|Tests unitarios, mocks y stubs]]: elegir casos, stubs frente a mocks e inyección de dependencias.
3. [[03 - Testing con Jest|Testing con Jest]]: dado-cuando-entonces, matchers, tests asíncronos, `jest.fn` y CI.
4. [[04 - Tests de front-end|Tests de front-end]]: regresión visual, performance, accesibilidad, E2E y React Testing Library.
