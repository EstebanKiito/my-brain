# Servidores y aplicaciones web — índice

Qué hay del otro lado de una request: cómo se pasó de servidores que entregaban archivos a aplicaciones web que generan cada respuesta, cómo se reparten las tareas entre frontend y backend con un framework y el patrón MVC, quién genera el HTML (CSR, SSR, SSG e ISR) y cómo se organiza un servidor en Express con middleware y un ORM.

Volver al [[Tecnologías y Aplicaciones Web/_Índice|mapa del ramo]].

> [!note] Origen
> Construido con las slides de la clase de desarrollo de servidores (evolución cliente-servidor, Apache y NGINX, mod_php y CGI, aplicación web, frontend y backend, frameworks, MVC en el stack del curso, CSR, SSR, SSG, ISR y Next.js, Express, middleware, driver, query builder y ORM, React y MVVM). El middleware se probó con Express.

## Orden de estudio
1. [[01 - Del servidor web a la aplicación web|Del servidor web a la aplicación web]]: servidores web, sitios estáticos y dinámicos, mod_php, CGI y coordinación cliente-servidor.
2. [[02 - Frontend, backend y frameworks web|Frontend, backend y frameworks web]]: responsabilidades, frameworks por lenguaje, MVC en el stack del curso y MVVM.
3. [[03 - Estrategias de rendering CSR, SSR, SSG e ISR|Estrategias de rendering CSR, SSR, SSG e ISR]]: dónde y cuándo se genera el HTML, y Next.js.
4. [[04 - Middleware y acceso a datos en el servidor|Middleware y acceso a datos en el servidor]]: Express, middleware con `next`, driver, query builder y ORM.
